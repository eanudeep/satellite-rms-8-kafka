Metrics Flow — follow the left arrows   (PULL model)
promauto.Inc()  /  promauto.NewGauge()  /  promauto.NewHistogram()
    │
    ▼  (numbers sit in RAM inside the Go process)
in-memory Prometheus registry
    │
    ▼  (promhttp.Handler() serialises the registry on demand)
GET /metrics endpoint  ◄──────  Prometheus scrapes every 15 s
                                │
                                ▼
                         Prometheus TSDB  (time-series storage)
                                │
                                ▼  (PromQL query from browser)
                             Grafana  ──►  Browser
Logs Flow — follow the right arrows   (buffered PUSH model)
fmt.Printf("...")  /  log.Println()
    │
    ▼  (containerd intercepts stdout of every pod)
/var/log/pods/.../0.log  on the Minikube node filesystem
    │
    ▼  (Vector Collector tails files continuously — DaemonSet, one pod per node, hostPath mount)
Vector Collector enriches each log line with Kubernetes metadata
    (pod namespace, pod name, container name, all pod labels)
    │
    ▼  (Kafka produce — one JSON event per log line, topic "loki-logs")
Kafka broker  (KRaft — no Zookeeper, single node, 1 h retention)
    │           messages survive here if Loki or the Forwarder restarts
    ▼  (Kafka consume — consumer group: vector-loki-forwarder, offset: latest)
Vector Forwarder extracts labels via VRL remap transform
    (namespace, pod, container, app, pipeline=kafka)
    │
    ▼  (HTTP POST /loki/api/v1/push)
Loki  (stores log lines indexed by labels)
    │
    ▼  (LogQL query from browser)
Grafana  ──►  Browser
The Key Structural Difference vs rms-7
rms-7  (Promtail, direct push):

  /var/log/pods/
      │
      ▼
  Promtail (DaemonSet)  ──────────────────────────────►  Loki
                             HTTP POST (synchronous)

  If Loki is restarting or slow, Promtail's push fails and
  those log lines are lost.


rms-8  (Vector + Kafka, buffered push):

  /var/log/pods/
      │
      ▼
  Vector Collector (DaemonSet)  ──►  Kafka (topic: loki-logs)
                                         │
                                         │  messages durable for 1 h
                                         │
                                         ▼
                              Vector Forwarder (Deployment)  ──►  Loki
                                                   HTTP POST

  Kafka acts as a durable buffer.  A Loki restart does not drop logs —
  they accumulate in the topic and are forwarded once Loki recovers.
  The Forwarder's consumer group offset ensures each message is
  delivered exactly once.
